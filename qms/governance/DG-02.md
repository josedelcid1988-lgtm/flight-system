# DG-02: Automation and skill validation and release

**Status:** Controlled-document draft for Quality review

## Lifecycle

Every automation is identified by its name, version, source, owner, intended use, prohibited uses, input schema, output schema, deterministic or model method, and target record. The owner submits a validation plan before release and retains the results against that version.

## Validation

Validation uses representative positive, negative, boundary, malformed-input, missing-evidence, replay, unauthorized-user, own-work, separation-of-duties, tampering and server-refusal cases. Expected answers are fixed before a run. A changed method, source, prompt, provider, model, schema or acceptance rule requires impact review and revalidation before the new version is used.

Validation shows that the tool follows its defined method; it does not establish that a draft is correct for a production record. A qualified person checks evidence, applicable requirements and every proposed conclusion.

## Release

Quality records the validation result, unresolved limitations, risk treatment, permitted users, approval, effective version, trigger rules and withdrawal path. A tool that fails validation remains disabled. A prior run remains traceable to its original version after a newer release.

## Monitoring and withdrawal

Review failures, refusals, repeated gaps, human rejections, stale inputs and provider changes. Disable and withdraw the affected version when a control fails. Retain the version, validation record, action history and reason for withdrawal.
