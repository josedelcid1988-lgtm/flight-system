# DG-01: AI and digital automation governance

**Status:** Controlled-document draft for Quality review  
**Applies to:** AI models, deterministic skills, and automated tools that produce analysis for a Flight System record

## Purpose

Set the controls for automated analysis used with Flight System quality and production records. Automation may organize evidence and draft analysis. It does not approve a record, release a work instruction, accept a finding, or make a product disposition.

## Required controls

1. A person remains accountable for every decision. A draft is visibly identified as a draft until a qualified person accepts it through the record's existing approval chain.
2. Deterministic methods are the default. The model adapter remains disabled until Quality has approved the use case and an authorized account has configured the server-side key setting.
3. Skill identity, version, input hash, output hash, actor, time, method, decision and referenced records are retained in the append-only AI action log. Never put credentials or raw secrets in that log.
4. A replay on identical inputs for the same target creates no second run record. A changed input is a new run and references the superseded analysis.
5. A skill may not invent measurements, inspection results, requirements, specifications, evidence, or signatures. Missing information is stated as a gap.
6. Separation of duties, own-work rules, authority, training, stamped approvals and server authorization remain enforced by the authoritative Flight rules.
7. AI output containing `[confirm]` is a prompt for a human to supply and verify information. It is never evidence or a finding until replaced and reviewed.
8. Tenant, supplier, customer and product data are used only for the approved purpose. No provider receives data unless the organization has approved that data flow.
9. An AI or automation result never becomes a drawing master, ERP posting, Jira disposition, PDM release, WI release, FAIR approval, conformity approval, or supplier acceptance.

## Change and incident control

Quality reviews each intended use, impact, validation evidence, permitted inputs, output destination and accountable decision owner before release. Disable an affected tool when its version, provider, validation, logging or record integrity cannot be confirmed. Preserve the incident evidence and investigate under the existing corrective-action process.

## Records

Keep approved purpose, risk assessment, validation, current version, configuration changes, run hashes, human review and disposition, incidents, and withdrawal history in the controlled QMS record. Export the current evidence set through the signed ISO/IEC 42001 evidence export.

## Approval

This file is a draft template. It has no released effect until imported into System QMS records, reviewed and released by three different people under the document-control workflow.
