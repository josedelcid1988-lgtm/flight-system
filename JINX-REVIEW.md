### 1. PostgreSQL account reads silently drop the authority profile
File: `server/db-postgres.mjs`, line 101.
Problem: `accounts()` selects `username, display_name, salt, hash, role, roles, created_at, created_by, sso` but NOT `profile`. `mapAccount()` reads `row.profile`, gets `undefined`, falls back to `{}`. Meanwhile `upsertAccount()` (line 107) writes `extraRoles`, `roleTraining`, `grants`, `grantHistory`, `supportAccess` into `profile`.
Effect: on PostgreSQL, training-gated extra roles stop applying, individually granted capabilities (conformity, aqi-sign) stop applying, support access reads false. SQLite is unaffected, so the backends silently disagree on authorization.
Fix: add `profile` to the SELECT column list. One word.

### 2. PostgreSQL backup procedure cannot work
File: `server/db-postgres.mjs`, line 167.
Problem: `backup()` spawns `pg_dump` with the full `FLIGHT_DATABASE_URL` connection URI stuffed into the `PGDATABASE` environment variable. Per PostgreSQL docs, `PGDATABASE` is a database *name*, not a URI; libpq treats the URI literally as a name and the connection fails.
Effect: the `--backup` CLI (`server/server.mjs:750`) and the documented procedure in `docs/DATABASES.md` cannot produce a PostgreSQL backup. Backups are a stated release requirement.
Fix: pass the URL as the `--dbname` argument to pg_dump (libpq parses `--dbname` values as URIs). Add a backup/restore smoke test for the PostgreSQL path; nothing covers it today.
