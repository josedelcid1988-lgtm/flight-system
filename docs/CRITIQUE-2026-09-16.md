## Design specificity verdict
Half-authored: aerospace domain layer on a generic admin-template composition (marketing hero, icon rail, KPI strip, pill tabs). Detector: dark-glow, bounce-easing, thin-border-wide-shadow ×4, nested-cards ×2, codex-grid-background (splash; decorative), text-occlusion on print-menu buttons, low-contrast 4.0:1 (#0a6cff on #eaf1ff), tiny-text 11px ×10–11/view, all-caps-body, layout-transition width ×2, side-tab.

## Priority issues
- [P0] Phone renders at 71% scale: 7-item nav.nav is 532px wide at 390px; 19/46 tap targets <44px. Fix: wrap/scroll rail or ≤5-item bottom bar under 700px. /impeccable adapt
- [P0] Next action never above the fold or in the hero (y=2341/3334/4410 on laptop/iPad/phone). Fix: sticky next-action bar with the one state CTA and blocked reason. /impeccable layout
- [P1] Hero + meta strip do not earn a task screen (444px + 313px, 9 admin controls, photo absent on iPad/phone). Fix: one-line record header, overflow menu, meta strip as disclosure. /impeccable distill
- [P1] Duplication: status 12 renderings, revision 5, op identity 5, user identity 6; "Awaiting issue" persists into Kitting. Fix: one authority per fact. /impeccable clarify
- [P2] Trust-critical copy and contrast: "understand this is a approval.", lowercase "reviewer:", "outside this 's scope", "only this local"; 4.0:1 contrast; 11px body text; all-caps runs. /impeccable polish
- [P3] Self-referential/disabled CTAs: "Review material kit" while on that tab; greyed Complete operation under Buy-off blocked. /impeccable harden

## Answers
1. Layout order is identity → admin → metadata → status → work; technician needs the reverse. Two-column execution layout is right but buried.
2. Heavy duplication (table above).
3. First correct click is "Review release" at the bottom of the task panel; ~14 clicks and 6 scrolls to first buy-off; empty-order note has no adjacent button; eye is drawn to "All work orders →".
